# LumaRoute v0.1 Internal Alpha 收口设计

- 日期：2026-08-21
- 状态：已批准
- 基线：`2026-08-07-lumaroute-v0.1-design.md`
- 发布级别：内部技术 Alpha

## 1. 目标

本阶段不新增产品能力，只为现有 v0.1 建立可信的真实运行和打包证据：

1. 以 Emby 为首个实机服务端，验证浏览、播放和进度回写闭环。
2. 验证独立 mpv 进程在 macOS Apple Silicon 与 Windows 安装包中可真实工作。
3. 验证 Windows 与 macOS Apple Silicon 约定产物可由 CI 构建。
4. 补齐播放启动失败后使用备用线路重建播放计划的专用自动化证据。
5. 将自动化、实机和环境限制统一记录到 v0.1 验收文档。

完成后得到可供内部测试的未签名 Alpha，不对普通用户公开分发。

Jellyfin 适配器、固定响应测试和现有容器契约继续保留，但 live Jellyfin
验证延期，不作为本阶段质量矩阵或 Internal Alpha 的硬门。

## 2. 非目标

- 不增加音轨、字幕、章节、音量或全屏控制。
- 不改变独立 mpv 进程和 JSON IPC 架构。
- 不实现播放中断后的自动换线。
- 不增加转码、聚合搜索、跨源匹配或更多媒体来源。
- 不要求 macOS 公证、Windows 签名、自动更新或公开 GitHub Release。
- 不借入 Nowen Video 的服务端、刮削、Go sidecar 或 libmpv Render Surface。

## 3. 与 v0.2 并行开发的边界

v0.1 收口与 v0.2 Player Basics 可以并行开发，但必须保持独立变更：

1. v0.1 收口基于当前 v0.1 基线，只接受验收、测试、打包和保持现有契约的缺陷修复。
2. v0.2 播放器扩展在独立分支或 PR 开发，不得进入 v0.1 Alpha 验收基线。
3. v0.1 发现的协议缺陷先在基线做最小修复，再同步到 v0.2。
4. v0.2 只能在 v0.1 Alpha 通过后合并，并重新运行完整 Alpha 回归。

这组门禁用于区分既有播放链路缺陷和新增播放器控制缺陷。

## 4. 自动化收口

### 4.1 播放启动换线

增加专用集成或端到端场景，证明：

1. 首选线路可以完成媒体浏览和初始播放计划生成。
2. 首选线路在 mpv 加载前出现可重试连接失败。
3. `PlaybackService` 按既有规则切换到备用线路并重新生成播放计划。
4. 新计划被加载，且播放会话 ID、媒体源和进度上报上下文使用新计划。
5. `401/403`、资源类 `4xx` 和不可直放错误不触发换线。

测试不得依赖真实私人地址、Token 或外部不稳定服务器。

### 4.2 Jellyfin 延期验证

现有临时 Jellyfin 契约保留为后续兼容性验证：

- 镜像使用不可变 digest。
- 覆盖认证、媒体库浏览、搜索、播放计划和进度上报。
- 夹具、日志和 CI 输出不得包含真实凭证。
- live 容器被跳过或媒体扫描失败时，不得单独导致本阶段质量矩阵失败。
- 本阶段不再为取得 live 容器绿灯改写媒体路径、样片、挂载或扫描等待逻辑。

Jellyfin 适配器及其固定响应单元测试仍属于 v0.1 回归范围；本次延期只影响
live 容器与实机证据，不删除 Jellyfin 产品能力。

### 4.3 真实 mpv 冒烟

当前平台的受控样片至少覆盖 H.264、H.265 和 AV1：

- 启动和文件加载。
- 暂停、恢复、跳转和停止。
- 开始、位置、暂停、跳转、停止或结束事件。
- 敏感请求头不进入 URL、命令行、普通配置或日志。

硬件不支持时允许软件解码；无法播放必须记录平台、mpv 构建和明确原因。

## 5. CI 与产物

CI 必须生成：

- Windows x64：MSI、NSIS EXE。
- macOS Apple Silicon：DMG。
- 每个产物对应的 SHA-256 文件。

Linux x64 AppImage/deb 质量、打包和原生 mpv 资格延期；Ubuntu 结果不得充当
本阶段硬门。macOS 与 Windows 还需要实机安装和播放证据。
macOS Intel runner 当前不可用，因此 `macos-13` / `x86_64-apple-darwin`
质量、打包和实机证据延期；Apple Silicon 结果不得充当 Intel 证据。

内部 Alpha 产物必须清楚标注：

- 未签名或未公证。
- 仅供内部技术验证。
- 可能触发操作系统安全警告。
- 不构成面向普通用户的公开发布。

## 6. 实机矩阵

### 6.1 平台

- macOS Apple Silicon：安装、首次启动、播放、退出和卸载。
- Windows x64：安装、首次启动、播放、退出和卸载。
- Linux x64：质量、打包和实机证据延期，不作为本阶段硬门。

### 6.2 服务端

macOS 与 Windows 分别以 Emby 完成首轮 Internal Alpha 实机闭环。每个平台至少覆盖：

1. 登录或读取既有安全凭证。
2. 浏览媒体库与媒体详情。
3. 原文件直放或不转码直接串流。
4. 暂停、恢复、跳转和停止。
5. 播放开始、进度、暂停、跳转和停止回写。
6. 应用退出后 mpv 与 IPC 资源得到清理。

服务器地址、用户名和 Token 只存在于测试人员的本地安全环境，不写入仓库或验收文档。

Jellyfin 的 macOS/Windows 实机组合延期到后续兼容性阶段，不阻塞本次
Internal Alpha；对应验收项保持未勾选并明确标记为 deferred。

## 7. 缺陷处理

- 仅修复阻止既有 v0.1 契约通过验收的缺陷。
- 修复不得扩大产品范围或改变既有架构。
- 发现需要改变范围或架构的问题时停止实现，先修订对应 spec。
- mpv 或 IPC 失败继续使用 `PlayerUnavailable` / `PlaybackFailed` 等既有稳定错误。
- 日志只记录脱敏后的平台、阶段和错误类别。

## 8. 验收记录

`docs/release/v0.1-acceptance.md` 是本阶段唯一验收记录。每个检查项必须附：

- 自动化测试名与 CI 运行 URL；或
- 测试日期、操作系统版本、安装包标识和结果；或
- 明确的环境限制与不通过原因。

以下结果全部满足后，才可标记 Internal Alpha 通过：

1. 全量质量门通过。
2. 播放启动备用线路重建计划的专用自动化通过。
3. Windows 与 macOS Apple Silicon CI 产物与 SHA-256 完整。
4. macOS Apple Silicon 与 Windows 的 Emby 实机闭环通过。
5. 真实 mpv 样片冒烟通过或对硬件限制有明确记录。
6. 凭证泄漏扫描为零发现。

Jellyfin live 容器与实机闭环、Linux quality/package、macOS Intel CI/实机证据、
签名、公证、公开许可证声明和普通用户分发继续作为后续门禁，不阻塞本次内部 Alpha。
