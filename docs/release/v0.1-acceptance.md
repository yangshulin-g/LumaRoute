# LumaRoute v0.1 Acceptance

Evidence map for design §14. Checkboxes receive a CI run URL or tester/date/OS note in the release PR. Failed evidence blocks release.

## Automated evidence

- [x] Two logical servers, each with two ServerId-validated lines. — `tests/e2e/onboarding.spec.ts` (local Playwright)
- [x] Timeout and 503 browsing fail over; 401 does not. — `tests/integration/line-failover.test.ts`
- [ ] Playback startup failure regenerates and loads a backup-line plan. — covered by unit tests in `packages/core` `PlaybackService`; dedicated E2E not yet added
- [x] Movie, series, season, and episode browsing. — domain + adapter unit tests; E2E browses Movies library
- [x] Current-server search. — `tests/e2e/browse-search-play.spec.ts`
- [x] mpv direct play and remux-only direct stream; transcode-only rejection. — adapter/player unit tests; E2E uses `FakePlayerEngine` (not real mpv)
- [x] Progress normally remains within 10 seconds. — `browse-search-play` asserts seeked progress `PositionTicks`; unit cadence in `ProgressReporter`
- [ ] Windows x64 MSI/NSIS, macOS Intel/Apple Silicon DMG, Linux x64 AppImage/deb. — `package.yml` defined; no successful run recorded for the current feature SHA
- [x] Credential leakage scans return zero findings. — `pnpm check:sensitive` / `check` gate
