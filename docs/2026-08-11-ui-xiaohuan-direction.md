# LumaRoute UI 方向：偏小幻（v0.1 视觉抛光）

- 日期：2026-08-11
- 状态：待用户批准（设计笔记，非产品范围变更）
- 选定方向：**2 = 偏小幻影视（Rodel Player）** — 浅色 / 系统感、更干净的详情与导航
- 参考：小幻为主；Hills Lite 仅借鉴侧栏+海报墙效率，不做深色影院风
- 约束：不改变已批准 spec 的功能边界；不改业务逻辑；页面仍只调应用服务
- 技术栈贴合：`Vue 3` + `vue-router` + `Pinia` + `@tanstack/vue-query` + `@tanstack/vue-virtual` + **原生 CSS 变量**（无 UI 组件库）

---

## 1. 现状摘要

信息架构已与 spec §9 对齐，壳层已存在：

| 区域 | 现状 | 观感问题 |
|------|------|----------|
| `AppShell` | 左栏服务器/库 + 顶栏搜索 + 内容区 | 边框扁平、无表面层级、英文文案 |
| Onboarding | 居中表单 | 可用，缺品牌与卡片感 |
| Home | 继续观看 + 库列表 | 继续观看像普通网格，缺横向「货架」感 |
| Library / Search | `VirtualPosterGrid` + `MediaCard` | 虚拟列表**按单列条目**排布，不像海报墙 |
| Detail | 标题/年份/简介/Play·Resume + `PlayerControls` | 无海报主视觉；操作与元数据层级弱 |
| Settings | 服务器列表 + 线路 CRUD | 功能完整，密度高、像调试台 |

依赖结论：**不要引入** Element Plus / Naive UI / Tailwind 等；用全局 CSS 变量 + 少量共享 class / 小组件即可在 1–2 天内「看起来像样」。

---

## 2. 视觉方向

### 2.1 气质

- **WinUI / Fluent 浅色桌面客户端**：干净、留白克制、清晰导航，而非影院沉浸深色。
- 表面层级：画布（canvas）→ 侧栏/顶栏（chrome）→ 卡片/海报（elevated）→ 主按钮（accent）。
- 圆角温和（8–12px），阴影极轻或仅用边框；避免紫渐变、霓虹光晕、过量圆角 pill。

### 2.2 色板（浅色为主）

建议在 `:root` 定义语义变量（实现时落在 `apps/desktop/src/styles.css`）：

| Token | 建议值 | 用途 |
|-------|--------|------|
| `--lr-canvas` | `#f3f6fa` | 页面底 |
| `--lr-surface` | `#ffffff` | 侧栏、顶栏、卡片、表单面板 |
| `--lr-surface-muted` | `#e8eef5` | 悬停、选中底、占位海报 |
| `--lr-border` | `#d5dde8` | 分隔线 |
| `--lr-text` | `#1b2430` | 主文字 |
| `--lr-text-secondary` | `#5a6b7d` | 次要说明、线路提示 |
| `--lr-accent` | `#2563eb` | 主操作（Play）、焦点环 |
| `--lr-accent-hover` | `#1d4ed8` | 主按钮悬停 |
| `--lr-danger` | `#b42318` | 删除确认 |
| `--lr-radius-sm` | `8px` | 输入、小按钮 |
| `--lr-radius-md` | `12px` | 卡片、侧栏项、详情海报 |
| `--lr-space` | `8px` 基数 | 间距用 8 / 12 / 16 / 24 |

字体：保持现有栈 `"Segoe UI", "PingFang SC", "Hiragino Sans GB", sans-serif`（跨平台系统感，贴近小幻 Fluent 气质）。

字号层级：

- 页面标题：`1.5–1.75rem` / semibold
- 区块标题：`1.125rem` / semibold
- 正文：`0.9375–1rem` / regular
- 海报标题 / 辅助：`0.8125–0.875rem` / secondary color

### 2.3 暗色

**v0.1 第一批：只交付浅色。**  
变量命名预留暗色（如 `[data-theme="dark"]`），**不做主题切换 UI**，避免范围膨胀。暗色可作为后续 0.5–1 天增量。

## 3. 信息架构（登录后主壳）

保持现有路由与壳结构，只改呈现与文案层级：

```text
┌──────────────┬─────────────────────────────────────────────┐
│ 侧栏 ~240px  │ 顶栏：当前服名（可选） + 搜索框 + 线路轻提示   │
│              ├─────────────────────────────────────────────┤
│ [品牌/Home]  │                                             │
│ ─────────    │              内容区（RouterView）             │
│ 服务器列表   │                                             │
│ ─────────    │                                             │
│ 媒体库列表   │                                             │
│ ─────────    │                                             │
│ 服务器设置   │                                             │
└──────────────┴─────────────────────────────────────────────┘
```

- **侧栏**：上 = 服务器切换；中 = 当前服媒体库；下 =「服务器设置」。选中态用浅底 + 左边强调条或字重，不用厚边框盒子堆叠。
- **顶栏**：单一搜索框（当前服内）；线路状态用小号次要文字（spec：显示当前线路但不频繁打扰）。
- **内容区**：白/浅表面，内边距 16–24px；详情可略放宽 max-width。
- **Onboarding**：全屏居中，不进 `AppShell`（与现路由一致）。

中文优先展示文案（Home→首页，Libraries→媒体库，Play→播放，Resume→继续播放，Search→搜索等）；`data-testid` 与测试选择器保持不变。

## 4. 关键页面（线框级）

### 4.1 登录 / Onboarding

```text
        ┌─────────────────────────────┐
        │  LumaRoute · 光路            │
        │  连接第一台 Emby / Jellyfin  │
        │  ┌───────────────────────┐  │
        │  │ 类型 · 显示名 · URL   │  │
        │  │ 用户名 · 密码         │  │
        │  │      [ 连接 ]         │  │
        │  └───────────────────────┘  │
        │  错误 / 成功提示（可执行）   │
        └─────────────────────────────┘
```

- 白底卡片 + 轻阴影/边框，置于浅画布中央。
- 成功后仍显示服务端名称与 ServerId（spec §9.1）；视觉上弱化为次要行。

### 4.2 首页

```text
首页
当前线路：主线路名（次要）

继续观看
[海报][海报][海报] → 横向可滚动货架（不强制虚拟）

媒体库
[电影库] [剧集库] …  大号入口块或侧栏重复入口的简洁列表
```

- 「继续观看」优先横向滚动一排；库入口可保留列表，样式做成轻量导航块。

### 4.3 库浏览

```text
媒体库名
当前线路：…（次要）

┌────┐ ┌────┐ ┌────┐ ┌────┐
│海报│ │海报│ │海报│ │海报│
│标题│ │标题│ │标题│ │标题│
└────┘ └────┘ └────┘ └────┘
 … 多列网格 + 虚拟滚动（保留分页/懒加载契约）
```

- **关键视觉修复**：海报墙必须是多列网格，而不是单列「一条一项」。
- 海报：`2:3`、圆角 `md`、悬停轻微抬升或边框；占位用 muted 色块。
- 仍走现有 `useLibraryItems` / `useSecureImage`；不改 Token-in-URL 策略。

### 4.4 搜索

```text
搜索「关键词」· N 条（可选）
[顶栏已搜时可弱化页内重复框，或保留同步输入]

多列海报网格（同库浏览）
空态：输入关键词以搜索当前服务器
```

- 范围文案明确「当前服务器」（不暗示聚合）。

### 4.5 详情（最小 PDP，对齐 spec §9.3）

```text
┌──────────┬────────────────────────────────┐
│          │ 标题                            │
│  海报    │ 年份 · kind · 时长              │
│  2:3     │                                │
│          │ [播放]  [继续播放 00:12:34]     │
│          │                                │
│          │ 简介（多行，次要色）             │
└──────────┴────────────────────────────────┘
播放控制条（独立 mpv 时的状态：Loading/Playing/Error…）
── 电视剧 ──
季： [S1] [S2] …（横向 chip）
剧集列表：E01 · 标题 …
```

- 主视觉用已有 `imageTag` + `useSecureImage` 拉 Primary 海报；**不**引入完整演职员/相关推荐（spec 明确不做）。
- 无 backdrop 字段时不做假背景图；可用极淡表面区分 header 区即可。
- Play / Resume 仍调 `playerStore`；控件样式化，逻辑不动。

### 4.6 服务器与线路管理

```text
服务器与线路
┌ 服务器列表（选中高亮）+ 上移/删除 ─────────────┐
│ 当前配置：名称输入                              │
│ 线路表：标签 · URL · 启停 · 排序 · 首选 · 敏感  │
│ [添加线路表单] + 测试状态                       │
│ 诊断面板（脱敏复制）                            │
└─────────────────────────────────────────────────┘
```

- 分区：服务器列表 | 当前配置 | 线路 | 诊断；用标题与间距分层，减少「按钮墙」感。
- 危险操作（删除）保持确认条；样式用 danger，不改流程。

## 5. 第一批改动清单（1–2 天，按优先级）

目标：**先看起来像样**，不碰播放管线 / core / 适配器契约。

| 优先级 | 项 | 落点 | 预估 |
|--------|----|------|------|
| P0 | 全局 CSS 变量 + 基础按钮/输入/链接样式 | `styles.css` + 各页 scoped 收敛 | 0.5d |
| P0 | `AppShell` 侧栏/顶栏表面、选中态、中文导航文案 | `AppShell.vue`、`ServerSwitcher`、`LibrarySidebar` | 0.3d |
| P0 | 海报墙改为**多列网格**虚拟化（保留懒加载/分页） | `VirtualPosterGrid.vue` | 0.5–0.8d |
| P0 | `MediaCard` 圆角、标题截断、悬停 | `MediaCard.vue` | 含上 |
| P1 | 详情：左海报 + 右元数据/主按钮布局 | `MediaDetailView.vue` | 0.3d |
| P1 | Onboarding 居中卡片 + 主按钮强调 | `OnboardingView.vue` | 0.2d |
| P1 | Home「继续观看」横向货架 + 标题层级 | `HomeView.vue` | 0.2d |
| P2 | Settings 分区与按钮密度整理（纯样式） | `ServerSettingsView` 等 | 0.2d |
| P2 | 搜索空态/结果标题 | `SearchView.vue` | 0.1d |

验收观感（人工）：登录页不像裸表单；进库后是海报墙而非单列列表；详情有海报与清晰 Play；侧栏有选中态。  
自动化：现有 UI 测试与 `data-testid` 保持绿灯；网格改动需补/调 `VirtualPosterGrid` 相关测试。

## 6. 不做清单（防膨胀）

- 不重做 / 不内嵌 mpv 画面（保持独立进程窗口）。
- 不引入重 UI 库或换框架（无 Tailwind / Uno / Element / Naive 除非另批）。
- 不做完整 PDP（演职员、相关推荐、分集缩略图墙）。
- 不做聚合首页 / 聚合搜索 / 跨源 UI。
- 不做暗色主题切换、自定义强调色、动画设计系统。
- 不做图标字体大套件；侧栏文字导航足够。
- 不改 Token 存储、HTTP、线路策略、进度上报等业务逻辑。
- 不把页面接到 SQLite / 凭证 / mpv IPC。

---

## 7. 与现有 Vue / 组件边界

- 页面继续通过 props / stores / `injectServices()` 调应用服务；DTO 仍在 core 适配器归一化。
- 样式层只动 `apps/desktop/src` 的 Vue SFC 与 `styles.css`。
- 图片继续 `useSecureImage`；禁止把 Token 放进 URL。
- 若多列虚拟网格需要小幅结构调整，保持对外 props（`items` / `hasNextPage` / `loadNext`）稳定，避免涟漪到业务 store。

---

## 8. 与已批准 spec 的关系

本笔记是 **§9 界面设计的视觉落地说明**，不修改 §4 范围。批准后实施时：

1. 按上表 P0→P2 改 UI；
2. 跑相关 UI 测试 + 质量门；
3. 若仅执行细节变化，可在 plan 中追加一行「UI 抛光任务」；**无需**为纯样式修订主 spec，除非要写进验收标准。

---

## 9. 请用户确认的决策点

1. **方向**：偏小幻浅色 Fluent —— 本文默认批准项。  
2. **暗色**：第一批不做切换（推荐） / 或第一批就加简易暗色。  
3. **文案**：界面中文优先（推荐） / 保持英文。  
4. **海报墙**：同意把 `VirtualPosterGrid` 从单列改为多列网格（推荐，否则「像样」难以达成）。
